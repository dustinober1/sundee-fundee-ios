# Sundee Fundee v1.5.1 — Polish & Hardening

**Status:** Design approved, awaiting implementation plan
**Date:** 2026-04-19
**Scope:** Patch release. No new features. Aggressive bias — user-visible polish, perf, reliability hardening, and code health.

## Goal

Ship a 1.5.1 patch that makes the app faster, more reliable, more polished, and more maintainable — without introducing any new features. Approach is audit-first: we don't know which items are highest-impact until we look, so prioritization happens after discovery.

## Non-Goals

- No new features
- No new CloudKit record types or schema changes
- No destructive migrations
- No App Store submission until explicitly approved by the user

## Phases

### Phase 1 — Parallel Audit

Four `Explore` subagents run concurrently. Each produces a findings report with severity tags (`high` / `med` / `low`) and concrete file:line references.

**1a. Performance audit**
- Fetch patterns on Dashboard, Programs, Maxes, Workout, Settings: flag sequential `await` chains that could be `async let` or `TaskGroup`
- Redundant `fetchAll` calls on `.onAppear` / `.task` across view re-entry
- Scroll performance on long lists (workout history, benchmarks, exercise picker)
- Expensive body recomputes (missing `Equatable` conformance on view inputs, over-broad `@Published` churn)
- Image/asset loading (share card rendering, theme assets)

**1b. Reliability audit**
- `SyncQueue` retry/backoff behavior, surfacing of stuck mutations to the user
- Guest → signed-in data migration path (does local data transfer cleanly?)
- Decode-resilience warning volume — are we silently swallowing bad records that should surface?
- CloudKit schema drift: compare `cloudkit-schema.json` to current model fields
- Offline edge cases in active workout logging
- Keychain session restore edge cases (deleted account, revoked token)

**1c. UX polish audit**
- Empty states inventory across every tab — consistency of voice, presence of CTAs
- Loading states inventory — spinners vs skeletons; Dashboard/Programs are priority
- Haptics gaps on key interactions: set complete, PR hit, plateau badge, share card save
- Accessibility pass: VoiceOver labels on icon-only buttons, Dynamic Type at XXL, contrast spot-check against WCAG AA
- Error message quality (are user-visible errors actionable?)

**1d. Code health audit**
- Review 1.5-touched files for simplification: share card renderer, plateau badge + popover, program session heat bar
- Test coverage gaps in `DomainLayer/Intelligence/*` (plateau detector, schedule reshuffler, substitution ranker, weekly load analyzer)
- Any `@unchecked Sendable` that could be tightened
- Any TODOs or FIXMEs left from 1.5 rush work

**Deliverable:** `docs/superpowers/specs/2026-04-19-v1.5.1-audit-findings.md` — consolidated report with severity-tagged findings.

### Phase 2 — Triage (User Approval Gate)

Present findings as three buckets:
- **must-fix** — regressions, bugs, correctness issues
- **should-fix** — high-impact polish/perf with low regression risk
- **skip** — low impact, high risk, or better deferred to 1.6

User approves the fix list before any code changes.

### Phase 3 — Execute

Fixes applied in priority order, grouped by area to keep commits coherent.

- Per-file commits dispatched to Haiku subagent per `CLAUDE.md` git workflow
- Tests added for any `DomainLayer` changes (Swift Testing or XCTest, matching neighbors)
- Manual simulator verification for UX changes on iPhone 17 Pro sim
- No destructive git operations without explicit confirmation

### Phase 4 — Regression Pass

Before tagging 1.5.1:
- Clean build: `xcodebuild ... -scheme SundeeFundee build` on iPhone 17 Pro sim
- Tests green: `cd SundeeFundee && swift test`
- Lint clean: `swiftlint --config .swiftlint.yml`
- Smoke-test golden paths in simulator:
  - Sign-in (Apple) + guest mode entry
  - Onboarding completion
  - Start + log a workout (sets, reps, weight)
  - Dashboard loads with recent data
  - Programs tab: enroll + view session
  - Maxes tab: log 1RM, verify plateau badge if applicable
  - Share card: render + save + preview variants
  - Sign out + sign back in (session restore)
- Bump `MARKETING_VERSION` to 1.5.1, bump `CURRENT_PROJECT_VERSION`
- Update `CHANGELOG.md`
- Tag `v1.5.1`
- Do NOT submit to App Store — wait for explicit user approval

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Audit surfaces more than fits in a patch release | Phase 2 triage gate — user decides scope |
| SyncQueue changes break offline replay | Add tests before changing; keep behavior changes behind targeted fixes, not rewrites |
| Guest→signed-in migration fix touches auth-critical code | Require explicit tests for migration path; verify on sim with both flows |
| UX polish introduces visual regressions | Manual sim verification for every UI change; spot-check on iPad Pro too |
| "Scope creep" into refactors | Stay focused on findings from the audit; anything not on the approved triage list is deferred |

## Success Criteria

- All must-fix items resolved
- ≥80% of should-fix items resolved
- No test regressions
- Clean lint
- Smoke test passes on iPhone + iPad sim
- Tag `v1.5.1` ready for user to submit to App Store

## Out of Scope (Deferred to 1.6+)

- Any new feature
- Schema migrations
- Large refactors unless directly motivated by audit findings
- Performance optimizations requiring architectural change
