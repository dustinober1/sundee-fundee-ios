# React Native iOS App Design Document

**Project:** Strength - Workout Tracking App
**Date:** 2026-02-16
**Goal:** Convert Next.js web app to React Native for iOS App Store + Android Play Store distribution

---

## Executive Summary

Migrate the existing Strength workout tracking web app (Next.js) to a React Native application for distribution on Apple iOS App Store and Google Play Store. The React Native rewrite will provide native performance, better App Store acceptance, and cross-platform support while maintaining the existing feature set and local-first architecture.

**Approach:** Expo with Development Builds (Recommended)
**Timeline:** 10-12 weeks to App Store submission
**Platforms:** iOS + Android

---

## Architecture Overview

### Technology Stack

**Core Framework:**
- React Native via Expo SDK 51+
- Expo Router for file-based navigation (similar to Next.js App Router)
- TypeScript for type safety

**UI & Styling:**
- React Native Paper for component library (Material Design 3)
- NativeWind for Tailwind CSS compatibility
- React Native Reanimated 3 for animations

**Data Layer:**
- AsyncStorage for local persistence (replaces IndexedDB/Dexie.js)
- React Context for state management (reuse existing contexts)
- Supabase for optional cloud sync (future feature)

**Charts & Visualization:**
- Victory Native for progress charts (replaces Recharts)

**Build & Deployment:**
- EAS (Expo Application Services) for builds
- EAS Submit for App Store/Play Store deployment

## Component & UI Migration Strategy

### UI Component Replacements

| Web Component | React Native Paper | Notes |
|---------------|-------------------|-------|
| `<Button>` | `<Button mode="contained">` | `mode` prop instead of `variant` |
| `<Card>` | `<Card>` | Similar API |
| `<Input>` | `<TextInput>` | More manual styling |
| `<Select>` | `<Menu>` or `<Dropdown>` | Different interaction pattern |
| `<Badge>` | `<Badge>` | Similar API |
| `<Alert>` | `<Banner>` | Similar API |

### Styling Migration

**NativeWind** enables ~90% compatibility with existing Tailwind classes:

```tsx
// Web
<Card className="p-4 rounded-lg shadow-md">
  <Button className="w-full bg-blue-500">Start</Button>
</Card>

// React Native
<Card style={tw`p-4 rounded-lg`}>
  <Button mode="contained" style={tw`w-full`}>Start</Button>
</Card>
```

### Design Tokens

Centralized design system in `constants/`:

```typescript
// constants/colors.ts
export const Colors = {
```

## Data Layer & State Management

### AsyncStorage Schema

Replace IndexedDB with AsyncStorage key-value storage:

```typescript
const KEYS = {
  USER: '@strength_user',
  ONE_REP_MAXES: '@strength_one_rep_maxes',
  ACTIVE_CYCLES: '@strength_active_cycles',
  COMPLETED_WORKOUTS: '@strength_completed_workouts',
  COMPLETED_SETS: '@strength_completed_sets',
} as const;
```

### Data Access Layer

Similar interface to existing Dexie helpers:

```typescript
// lib/storage/database.ts
export async function createUser(data: Omit<User, 'id' | 'createdAt'>): Promise<User>
export async function getUser(): Promise<User | null>
export async function updateUser(id: string, updates: Partial<User>): Promise<void>
export async function saveOneRepMax(oneRepMax: OneRepMax): Promise<void>
export async function getLatest1RM(userId: string, exerciseId: string): Promise<OneRepMax | undefined>
export async function saveActiveCycle(cycle: ActiveCycle): Promise<void>
export async function getActiveCycles(userId: string): Promise<ActiveCycle[]>
```

### State Management

**Approach:** Reuse existing React Context pattern (no Redux needed for current scope)

**Contexts to migrate:**
- `UserContext` - User profile, 1RMs, sync status (95% compatible)
- `ExerciseContext` - Program data, calculations (100% compatible)

**Migration effort:** Minimal - mostly import path changes

## Navigation & Routing

### Expo Router Structure

File-based routing identical to Next.js App Router:

```
app/
├── _layout.tsx              # Root layout
├── index.tsx                # / (redirects based on auth)
├── onboarding.tsx           # /onboarding
├── (tabs)/                  # Tab navigator
│   ├── _layout.tsx          # Tab configuration
│   ├── dashboard.tsx        # /dashboard
│   ├── programs.tsx         # /programs
│   ├── workout.tsx          # /workout
│   └── progress.tsx         # /progress
└── workout/
    └── [id].tsx             # /workout/:id (dynamic)
```

### Navigation API

| Next.js | Expo Router | Notes |
|---------|-------------|-------|
| `useRouter()` | `useRouter()` | Identical API |
| `Link href="..."` | `Link href="..."` | Identical API |
| `redirect()` | `<Redirect href="..." />` | Component instead of function |
| `params.id` | `useLocalSearchParams()` | Hook-based |

### Deep Linking

**App Scheme:** `strengthapp://`
**Universal Links:** `https://strengthapp.com` (future web fallback)

## Testing Strategy

### Testing Stack

| Purpose | Web | React Native |
|---------|-----|--------------|
| Unit/Integration | Vitest | Jest |
| Component | RTL | React Native Testing Library |
| E2E | Playwright | Detox |

### Test Coverage Targets

- **70%** Unit/integration tests (business logic, calculations, storage)
- **20%** Component tests (critical flows, form validation)
- **10%** E2E tests (onboarding, workout logging)

### Test Migration

**Keep/copy from web app:**
- ✅ Business logic tests (calculations, recommendations)
- ✅ Context tests (with minimal mock changes)
- ✅ Utility function tests

**Rewrite for React Native:**
- ❌ Component tests (different rendering API)
- ❌ E2E tests (completely different framework)

**Three build profiles:**

2. **Preview** - TestFlight distribution
3. **Production** - App Store/Play Store submission

### App Store Submission Checklist

**Phase 1: Apple Developer Setup**
- [ ] Enroll in Apple Developer Program ($99/year)
- [ ] Create App Store Connect account
- [ ] Generate distribution certificates
- [ ] Register Bundle Identifier
- [ ] Create provisioning profiles

**Phase 2: App Store Connect**
- [ ] Create new app listing
- [ ] Upload screenshots (iPhone 6.7", 6.5", 5.5")
- [ ] Write description and keywords
- [ ] Set age rating
- [ ] Configure pricing (Free)

**Phase 3: Privacy & Legal**
- [ ] Privacy policy URL
- [ ] Data privacy details
- [ ] App Privacy Report
- [ ] Export compliance
- [ ] Content rights acknowledgment

**Phase 4: Build & Submit**
- [ ] Build with `eas build --platform ios --profile production`
- [ ] Test on TestFlight
- [ ] Submit for review
- [ ] Address feedback

**Review Timeline:** 1-3 days typical, up to 2 weeks for complex apps

## Development Phases

**Goal:** Working dev environment and basic app structure

- Configure NativeWind + React Native Paper
- Create file structure
- Set up Expo Router with tab navigation
- Implement Providers wrapper
- Copy types from web app
- Set up AsyncStorage layer
- Create placeholder screens

**Deliverable:** App builds and runs on iOS + Android with 4 tabs

---

### Phase 2: Data Layer & Contexts (Week 3)
**Goal:** Local storage and state management working

- Implement AsyncStorage database layer
- Write storage operation tests
- Port User context from web app
- Port Exercise context from web app
- Copy business logic (calculations, recommendations)
- Copy program data JSON files
- Test data flow end-to-end

**Deliverable:** Can create user, load programs, store data locally

---

- Write component tests

## Conclusion

This design provides a comprehensive roadmap for migrating the Strength workout tracking app from Next.js to React Native. The Expo with Development Builds approach offers the best balance of ease of development, native performance, and App Store acceptance for someone new to React Native.

**Estimated Timeline:** 10-12 weeks to App Store submission
**Primary Platform:** iOS App Store
**Secondary Platform:** Google Play Store (simultaneous launch)
**Maintenance:** Updates via EAS (OTA updates available with Expo)
