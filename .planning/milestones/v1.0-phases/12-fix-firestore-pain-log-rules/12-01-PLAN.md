Add a new `match` block inside the existing `match /users/{userId}` block, after the existing `match /{subcollection}/{docId}` block. The new block targets the 2-level nested pain log path:

```
match /injuries/{injuryId}/painLogs/{logId} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```

This is needed because Firestore's single-segment wildcard `/{subcollection}/{docId}` only matches paths exactly 2 segments deep under `/users/{userId}`. The pain log path is 4 segments deep (`injuries/{injuryId}/painLogs/{logId}`), so it needs its own explicit match.

Do NOT use the recursive wildcard `/{path=**}` — the explicit path is more secure and self-documenting per research recommendation.

Add a comment above the new block: `// 2-level nested subcollection: pain logs under an injury profile`
