    **AuthButton.tsx** — Reusable full-width button component:
    - Props: `{ title: string, onPress: () => void, isLoading: boolean, error: string | null, icon?: React.ReactNode, variant: 'primary' | 'secondary' | 'text', disabled?: boolean }`
    - When `isLoading=true`: show ActivityIndicator inside the button, disable all sibling buttons (parent manages this via `disabled` prop)
    - When `error` is non-null: show error message as small text below the button (inline, NOT modal — per locked decision)
    - Styling: full-width, rounded corners, Art Deco palette. Primary = NAVY background + CREAM text. Secondary = CREAM background + NAVY text + NAVY border. Text = transparent background + NAVY text (for "Continue as Guest").
    - Per locked decision: "button-level spinner (tapped button shows spinner, all buttons disabled during auth)"

    **AuthButton.test.tsx** — Unit tests:
    - Renders title text
    - Shows ActivityIndicator when isLoading=true
    - Shows error message when error is provided
    - Calls onPress when tapped
    - Does NOT call onPress when disabled

    **OfflineBanner.tsx** — Subtle connectivity indicator:
    - Uses `expo-network` to detect online/offline state via `useNetworkState()` hook
    - When offline: renders a subtle banner at top of screen "You're offline. Sign in requires a connection." (per locked decision)
    - When online: renders nothing
    - Style: small text, muted color, not alarming

    **sign-in.tsx** — Auth screen (per ALL locked design decisions):
    - Layout: ScrollView with centered content, Art Deco styling
    - Top: App logo (placeholder Image) centered with tagline "Strength Training, Evolved" below it
    - Middle: Stacked full-width auth buttons with proper ordering per locked decision:
      - **iOS**: Apple Sign-In (top) -> Email Sign-In -> "Continue as Guest" (de-emphasized text link)
      - **Android**: Google Sign-In (top) -> Email Sign-In -> "Continue as Guest" (de-emphasized text link)
      - **Web**: Google Sign-In (top) -> Email Sign-In -> "Continue as Guest" (de-emphasized text link)
    - Use `Platform.OS` to conditionally render Apple vs Google button
    - Email section: Two TextInput fields (email, password) + "Sign In" button + "Create Account" link that toggles to sign-up mode
    - Sign-up mode: Same fields + "Sign Up" button. On success, navigate to verify-email screen.
    - Each button wires to its respective hook (useAppleSignIn, useGoogleSignIn, useEmailAuth, useGuestSignIn)
    - Loading state: When any auth is in progress, ALL buttons are disabled (per locked decision)
    - Error state: Inline error messages appear below the failed button/field (per locked decision)
    - Include `<OfflineBanner />` at top
    - Background: CREAM. Text: NAVY. Accent buttons: ORANGE.
    - After successful auth, `onAuthStateChanged` in SessionProvider will trigger navigation automatically (no manual navigation needed)

    **verify-email.tsx** — Email verification waiting screen:
    - Message: "Check your email" with instruction to verify before continuing
    - "Resend Verification Email" button (calls `user.sendEmailVerification()`)
    - "Back to Sign In" link (calls signOut to return to auth screen)
    - Simple, clean design with Art Deco styling
    - When user returns after verifying: they sign in again on the auth screen (Firebase does not auto-detect verification — user must re-sign-in)

    - Otherwise: render `<Stack>` with `(tabs)` screen
