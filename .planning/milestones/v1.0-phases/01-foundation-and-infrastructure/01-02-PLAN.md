    **UserRepository.ts** — Interface definition:
    ```typescript
    export interface UserProfile {
      uid: string;
      email: string | null;
      displayName: string | null;
      isAnonymous: boolean;
      createdAt: string;    // ISO 8601
      lastSignInAt: string; // ISO 8601
      authProvider: 'apple' | 'google' | 'email' | 'anonymous';
    }

    export interface UserRepository {
      createOrUpdateUser(profile: UserProfile): Promise<void>;
      getUser(uid: string): Promise<UserProfile | null>;
      deleteUser(uid: string): Promise<void>;
    }
    ```

    **FirestoreUserRepo.ts** — Firestore implementation:
    - Implements `UserRepository` interface
    - `createOrUpdateUser`: calls `firestore().collection('users').doc(uid).set(profile, { merge: true })` — uses merge to avoid overwriting fields set by other clients
    - `getUser`: calls `firestore().collection('users').doc(uid).get()`, returns data or null if doc doesn't exist
    - `deleteUser`: calls `firestore().collection('users').doc(uid).delete()`
    - Import firestore from platform-aware module (`src/firebase/firestore`)
    - This satisfies AUTH-07 (Roadmap Success Criterion 4): "Authenticated user data syncs to Firestore and is visible on a second device after sign-in"

    **LocalUserRepo.ts** — AsyncStorage implementation for guest mode:
    - Implements `UserRepository` interface
    - `createOrUpdateUser`: stores JSON to AsyncStorage under key `user_profile`
    - `getUser`: retrieves and parses from AsyncStorage, returns null if not found
    - `deleteUser`: removes key from AsyncStorage
    - Guest users use this so their profile persists locally without Firestore
