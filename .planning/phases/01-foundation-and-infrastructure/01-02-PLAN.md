  <action>
    Write tests first (RED), then implement each module (GREEN).

    **AuthContext.tsx** — Create React context with:
    - `SessionProvider` component: registers `onAuthStateChanged` listener in useEffect, stores user and isLoading in state, provides signIn/signOut functions
    - `useSession` hook: consumes context, throws if used outside provider
    - Session type: `{ user: FirebaseAuthTypes.User | null, isLoading: boolean, isGuest: boolean }`
    - `isGuest` derived from `user?.isAnonymous === true`
    - `signOut` implementation: calls `auth().signOut()`, then `AsyncStorage.clear()` to wipe all local data per locked decision
    - Import auth from platform-aware module (`src/firebase/auth`)

    **useAppleSignIn.ts** — Hook returning `{ signIn, isLoading, error }`:
    - Calls `AppleAuthentication.signInAsync` with FULL_NAME + EMAIL scopes
    - Extracts identityToken, creates `AppleAuthProvider.credential(identityToken, nonce)`
    - Calls `auth().signInWithCredential(credential)`
    - On first sign-in: stores `fullName` to `expo-secure-store` (Apple only provides name once per user decision — see Pitfall 2 in RESEARCH)
    - Error handling: catches and maps via authErrors.ts

    **useGoogleSignIn.ts** — Hook returning `{ signIn, isLoading, error }`:
    - Calls `GoogleSignin.configure({ webClientId: process.env.EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID })` once
    - Calls `GoogleSignin.hasPlayServices({ showPlayServicesUpdateDialog: true })`
    - Calls `GoogleSignin.signIn()`, extracts `idToken` from `result.data`
    - Creates `GoogleAuthProvider.credential(idToken)`, calls `auth().signInWithCredential`
    - Error handling: catches and maps via authErrors.ts

    **useEmailAuth.ts** — Hook returning `{ signUp, signIn, isLoading, error }`:
    - `signUp(email, password)`: calls `createUserWithEmailAndPassword`, then `user.sendEmailVerification()`. Returns `{ needsVerification: true }`.
    - `signIn(email, password)`: calls `signInWithEmailAndPassword`. If `user.emailVerified === false`, calls `signOut()` and throws error "Please verify your email before signing in." per locked decision.
    - Error handling: catches and maps via authErrors.ts

    **useGuestSignIn.ts** — Hook returning `{ signIn, upgrade, isLoading, error }`:
    - `signIn()`: calls `auth().signInAnonymously()`
    - `upgrade(credential)`: calls `auth().currentUser?.linkWithCredential(credential)` — converts anonymous account to permanent account, preserving UID and Firestore data per locked decision (guest-to-auth merge)
    - Error handling: catches and maps via authErrors.ts

    **authErrors.ts** — Maps Firebase Auth error codes to user-friendly messages:
    - `auth/email-already-in-use` -> "An account with this email already exists"
    - `auth/invalid-email` -> "Please enter a valid email address"
    - `auth/wrong-password` -> "Incorrect password. Please try again"
    - `auth/user-not-found` -> "No account found with this email"
    - `auth/too-many-requests` -> "Too many attempts. Please try again later"
    - `auth/network-request-failed` -> "Network error. Please check your connection"
    - `auth/invalid-credential` -> "Sign-in failed. Please try again"
    - Default: "Something went wrong. Please try again"
    - Export `getAuthErrorMessage(error: unknown): string`
