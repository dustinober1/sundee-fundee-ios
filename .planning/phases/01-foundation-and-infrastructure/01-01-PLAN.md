  <action>
    Create `SundeeFundeeRN/firestore.rules` with the user-owned data pattern from RESEARCH.md:

    ```
    rules_version = '2';
    service cloud.firestore {
      match /databases/{database}/documents {
        // Default: deny all reads and writes
        match /{document=**} {
          allow read, write: if false;
        }

        // User profile: only the owner can read/write
        match /users/{userId} {
          allow read, write: if request.auth != null && request.auth.uid == userId;

          // All user subcollections (workouts, injuries, cycle logs, etc.): owner-only
          match /{subcollection}/{docId} {
            allow read, write: if request.auth != null && request.auth.uid == userId;
          }
        }

        // Programs collection: authenticated users can read, no writes from client
        // (Programs are admin-seeded via Firebase Console or Cloud Functions)
        match /programs/{programId} {
          allow read: if request.auth != null;
          allow write: if false;
        }

        // WODs collection: authenticated users can read, no client writes
        match /wods/{wodId} {
          allow read: if request.auth != null;
          allow write: if false;
        }
      }
    }
    ```

    Create `SundeeFundeeRN/firestore.rules.test.ts` using `@firebase/rules-unit-testing` (install as dev dependency: `npm install --save-dev @firebase/rules-unit-testing firebase-admin`):

    ```typescript
    import { initializeTestEnvironment, assertSucceeds, assertFails, RulesTestEnvironment } from '@firebase/rules-unit-testing';
    import { readFileSync } from 'fs';

    let testEnv: RulesTestEnvironment;

    beforeAll(async () => {
      testEnv = await initializeTestEnvironment({
        projectId: 'sundee-fundee-test',
        firestore: {
          rules: readFileSync('firestore.rules', 'utf8'),
        },
      });
    });

    afterAll(async () => {
      await testEnv.cleanup();
    });

    afterEach(async () => {
      await testEnv.clearFirestore();
    });
    ```

    Test cases to include:
    - Unauthenticated user CANNOT read /users/any-uid (assertFails)
    - Authenticated user CAN read/write their own /users/{their-uid} (assertSucceeds)
    - Authenticated user CANNOT read/write another user's /users/{other-uid} (assertFails)
    - Authenticated user CAN read/write their own subcollections /users/{uid}/workouts/doc1 (assertSucceeds)
    - Authenticated user CANNOT write to /programs/any-id (assertFails)
    - Authenticated user CAN read /programs/any-id (assertSucceeds)
    - Authenticated user CAN read /wods/any-id (assertSucceeds)
    - Unauthenticated user CANNOT read /programs or /wods (assertFails)

    Note: These tests require the Firebase Emulator to run. Add a script to package.json: `"test:rules": "firebase emulators:exec --only firestore 'npx jest firestore.rules.test.ts'"`. The tests validate rules locally before deployment.

    This MUST be deployed before any Firestore data writes occur in later plans. The rules enforce:
    - Default deny on all paths
    - User data (/users/{uid} and all subcollections) accessible only by the owning user
    - Programs and WODs readable by any authenticated user, not writable from client
    - Anonymous (guest) users with Firebase auth tokens CAN access their own /users/{uid} path

    Note: Actual deployment to Firebase requires `firebase deploy --only firestore:rules` which needs the Firebase CLI and project access. The file is written here; deployment happens as a user_setup step or CI pipeline.
