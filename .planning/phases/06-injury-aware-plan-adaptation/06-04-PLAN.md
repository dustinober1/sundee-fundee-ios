    **1. Mid-workout injury context change prompt:**

    The existing `_handleAdaptedProgramUpdate` method already detects program changes via `_buildSessionSignature` and `_hasMeaningfulPrescriptionChange`. Since Plan 02 swapped the listen target to `injuryAdaptedActiveProgramProvider`, injury-driven changes will automatically trigger this method.

    Update the COPY in `_promptForPhaseUpdate` to handle injury-specific context. The method currently shows generic "Workout Update Available" dialog. Modify it to detect whether the change was injury-driven:

    - Add a parameter `bool isInjuryRelated` to `_promptForPhaseUpdate` (default false).
    - In `_handleAdaptedProgramUpdate`, determine if injury context changed by comparing `_session.recoveryPrepExercises.isNotEmpty` vs the new session's `recoveryPrepExercises.isNotEmpty`, OR by checking if any exercise's `injuryReplacedOriginal` fields differ.
    - If injury-related, show dialog with:
      - Title: "Injury Update Available"
      - Content: "Your injury profile changed during this workout. Updated safe exercise prescriptions are available. Apply them to remaining exercises, or keep your current session."
      - Actions: "KEEP CURRENT" (TextButton) and "APPLY SAFE" (ElevatedButton)
    - If NOT injury-related (cycle adaptation change), keep existing dialog copy.
    - The APPLY/DEFER logic remains identical — `_applyDeferredUpdate()` / `_hasDeferredUpdate = true`.

    **2. Override revert-to-contraindicated warning:**

    Add a "Revert to original" action to `_ExerciseCard` when `exercise.injuryReplacedOriginal != null` AND `!exercise.isContraindicatedOriginal`:
    - Add a small TextButton below the replacement info: "Use original instead" in grey text
    - Tapping shows AlertDialog:
      - Title: "⚠ Warning: Contraindicated Exercise"
      - Content: "'{injuryReplacedOriginal}' was replaced due to your active injury. Performing it may worsen your condition or cause harm.\n\nThis app does not provide medical advice. Consult a healthcare professional before proceeding."
      - Actions:
        - "STAY SAFE" (TextButton, primary color) — dismisses dialog, no change
        - "REVERT ANYWAY" (TextButton, Colors.red foreground) — applies the revert
    - On revert: This is a LOCAL-ONLY override for the current workout session. Do NOT modify the provider or Firestore.
      - Maintain a `Set<String> _revertedExercises` in the StatefulWidget state (keyed by exercise ID)
      - When rendering `_ExerciseCard`, check if exercise is in `_revertedExercises`:
        - If yes: render the ORIGINAL exercise name (from `injuryReplacedOriginal`) instead of the replacement, and show the red "Using contraindicated exercise" warning banner
        - If no: render normally with replacement labels
    - This revert does NOT affect set logging — the user simply sees the original exercise name and can log against it. The adaptation data in the provider is unchanged.

    **Important behavioral notes from CONTEXT.md:**
    - "Apply immediately for upcoming workouts, never rewrite completed history" — the mid-workout prompt handles this correctly since it only affects the current session view.
    - "No disable toggle while injury status is active" — there is NO UI to disable injury adaptation globally. The override is per-exercise, per-session only.
