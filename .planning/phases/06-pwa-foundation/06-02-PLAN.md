<task type="auto">
  <name>Task 1: Add iOS meta tags and manifest link to layout.tsx</name>
  <files>src/app/layout.tsx</files>
  <action>
Update the `metadata` export in `src/app/layout.tsx` to add:

1. `manifest: '/manifest.json'` — generates `<link rel="manifest" href="/manifest.json">`

2. `icons.apple` array — generates `<link rel="apple-touch-icon">`
   ```typescript
   icons: {
     apple: [
       { url: '/icons/apple-touch-icon.png', sizes: '180x180', type: 'image/png' },
     ],
   },
   ```

3. `appleWebApp` object — generates iOS-specific meta tags:
   ```typescript
   appleWebApp: {
     capable: true,                        // → <meta name="mobile-web-app-capable">
     title: 'SundeeFundee',               // → <meta name="apple-mobile-web-app-title">
     statusBarStyle: 'black-translucent', // → <meta name="apple-mobile-web-app-status-bar-style">
   },
   ```

4. `other` object — CRITICAL: adds the Apple-specific capable tag:
   ```typescript
   other: {
     'apple-mobile-web-app-capable': 'yes',
   },
   ```

**Why both `appleWebApp.capable` AND `other['apple-mobile-web-app-capable']`?**
Next.js `appleWebApp.capable: true` generates `mobile-web-app-capable` (W3C standard), NOT `apple-mobile-web-app-capable` (Apple-specific). The success criteria requires the `apple-` prefixed version, so we add it explicitly via `other`. Both tags can coexist.

Final metadata export should be:
```typescript
export const metadata: Metadata = {
  title: 'Sundee-Fundee',
  description: 'Track your workouts and fitness goals',
  manifest: '/manifest.json',
  icons: {
    apple: [
      { url: '/icons/apple-touch-icon.png', sizes: '180x180', type: 'image/png' },
    ],
  },
  appleWebApp: {
    capable: true,
    title: 'SundeeFundee',
    statusBarStyle: 'black-translucent',
  },
  other: {
    'apple-mobile-web-app-capable': 'yes',
  },
}
```

<task type="auto">
  <name>Task 2: Update middleware matcher and Playwright config</name>
  <files>middleware.ts, playwright.config.ts</files>
  <action>
**Part A: Update middleware.ts matcher**

Change the config.matcher array to exclude PWA static files from Supabase auth processing:

Current:
```typescript
matcher: [
  '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
],
```

Updated:
```typescript
matcher: [
  '/((?!_next/static|_next/image|favicon.ico|manifest\\.json|sw\\.js|workbox-.*\\.js|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
],
```

Added exclusions:
- `manifest\\.json` — manifest must not go through auth
- `sw\\.js` — future service worker (Phase 7)
- `workbox-.*\\.js` — future Workbox chunks (Phase 7)

**Part B: Update playwright.config.ts**

Add `serviceWorkers: 'block'` to the `use` block:

Current:
```typescript
use: {
  baseURL: 'http://localhost:3000',
  trace: 'on-first-retry',
},
```

Updated:
```typescript
use: {
  baseURL: 'http://localhost:3000',
  trace: 'on-first-retry',
  serviceWorkers: 'block',
},
```

This prevents any future service worker from intercepting test network requests. Safe to add before any SW exists — it's a no-op until Phase 7.
  </action>
  <verify>
- `grep 'manifest\\.json' middleware.ts` shows the exclusion
- `grep 'sw\\.js' middleware.ts` shows the exclusion
- `grep "serviceWorkers: 'block'" playwright.config.ts` shows the config
  </verify>
  <done>Middleware excludes PWA static files; Playwright blocks service workers.</done>
</task>
