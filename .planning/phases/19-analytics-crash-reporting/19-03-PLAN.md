<task type="auto">
  <name>Task 1: Install expo-updates and configure EAS Update</name>
  <files>
    package.json
    app.json
    eas.json
  </files>
  <action>
1. **Install expo-updates:**
   ```bash
   npx expo install expo-updates
   ```
   This installs the SDK-compatible version and updates package.json.

2. **Run EAS Update configure:**
   ```bash
   eas update:configure
   ```
   This automatically adds `runtimeVersion` and `updates.url` to app.json/app.config.js. Accept defaults. If it asks about platform, select "All".

3. **Read the updated eas.json** (eas update:configure may modify it). Then manually ensure the following channel configuration exists:
   - `build.preview` must have `"channel": "preview"`
   - `build.production` must have `"channel": "production"`
   - Do NOT add channel to `build.development` (dev builds use development client, not OTA updates)
   - Preserve ALL existing fields (developmentClient, distribution, env, submit sections)

4. **Verify app.json** has `runtimeVersion` set. If `eas update:configure` set it to a semver policy like `{ "policy": "appVersion" }` or a fixed string, that's fine. If it's missing, add `"runtimeVersion": { "policy": "appVersion" }` to the expo section.

5. **Verify app.json** has `updates.url` set. It should be `https://u.expo.dev/{projectId}`. If missing, the `eas update:configure` command failed — rerun it.

IMPORTANT: expo-updates is a native module. After this plan completes, a new EAS binary build is needed before OTA updates can be tested. The Phase 18 dev build will NOT receive OTA updates. This is expected — the checkpoint task documents this for the user.
  </action>

  </verify>
