Create `firestore.rules` at the repo root by copying the existing rules from `.claude/worktrees/serene-poincare/SundeeFundeeRN/firestore.rules` and extending with:

1. **Depth-2 wildcard** (fixes painLogs gap): Add `match /{subcollection}/{docId}/{nested=**}` under `/users/{userId}` with the same `request.auth.uid == userId` check.

2. **premiumEntitlement field block** (SEC-02): Replace the single `allow read, write` on `/users/{userId}` with separate rules:
   - `allow read`: auth + owner
   - `allow create`: auth + owner + `!('premiumEntitlement' in request.resource.data)` (cannot create user doc with premiumEntitlement)
   - `allow update`: auth + owner + `!request.resource.data.diff(resource.data).affectedKeys().hasAny(['premiumEntitlement'])` (cannot modify premiumEntitlement)
   - `allow delete`: auth + owner

The exact rules structure from RESEARCH.md Section "SEC-01 + SEC-02: Firestore Security Rules" should be used. Keep all comments explaining the security rationale.
