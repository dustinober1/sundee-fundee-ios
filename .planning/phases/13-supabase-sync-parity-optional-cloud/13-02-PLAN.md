  <files>flutter_app/lib/services/sync_service.dart</files>
  <action>
    Create `flutter_app/lib/services/sync_service.dart` that mirrors v1.1's sync-engine.ts adapted for Drift + Supabase.

    **Class structure:**
    ```dart
    class SyncService {
      final AppDatabase _db;
      final SupabaseClient _supabase;
      static const _queueKey = 'sync_pending_workout_ids';
    ```

    **Required methods:**

    1. `Future<void> pushWorkout(int localWorkoutId)`:
       - Fetch workout from Drift `completedWorkouts` by id
       - Ensure syncId: if null, generate UUID v4, save to Drift BEFORE Supabase call
       - Resolve parent cycle's syncId (look up `activeCycles` row, ensure ITS syncId exists too — push cycle first if needed)
       - Fetch completed sets for this workout
       - Ensure each set has syncId (generate + save if null)
       - Upsert workout row to Supabase `completed_workouts` table
       - Upsert each set to Supabase `completed_sets` table
       - Push any OneRepMaxes and PersonalRecords for this workout (resolve their syncIds too)
       - Use `withRetry` wrapper for Supabase calls

    2. `Future<void> pushCycle(int localCycleId, String userId)`:
       - Ensure syncId on cycle, upsert to Supabase `active_cycles`
       - Called internally by pushWorkout when parent cycle lacks syncId

    3. `Future<void> pullLatest()`:
       - Pull all user's data from Supabase (completed_workouts, completed_sets, active_cycles, one_rep_maxes, personal_records)
       - For each cloud row, check if syncId already exists in Drift
       - If exists: update (cloud wins, matching v1.1 semantics)
       - If not: insert with the cloud syncId
       - Pull order: active_cycles → completed_workouts → completed_sets → one_rep_maxes → personal_records (FK order)

    4. `Future<void> uploadAllLocalData(String userId)`:
       - Called on first sync after sign-in
       - Push all local data that has no syncId yet
       - Order: active_cycles → completed_workouts → completed_sets → one_rep_maxes → personal_records

    5. `Future<void> enqueue(int workoutId)`:
       - Add workoutId to SharedPreferences JSON list if not already present

    6. `Future<void> dequeue(int workoutId)`:
       - Remove workoutId from SharedPreferences JSON list

    7. `Future<List<int>> getQueue()`:
       - Read workout ID list from SharedPreferences

    8. `Future<void> drainQueue()`:
       - Get queue, push each workout, dequeue on success
       - Continue on individual failures (don't abort entire drain)

    9. `Future<T> withRetry<T>(Future<T> Function() fn, {int maxAttempts = 3})`:
       - Retry with exponential backoff (1s, 2s, 4s)
       - Rethrow on final failure

    **Transform helpers (private methods):**

    - `Map<String, dynamic> _workoutToSupabaseRow(CompletedWorkout w, String userId, String syncId, String cycleSyncId)` — maps Drift workout to Supabase row format
    - `Map<String, dynamic> _setToSupabaseRow(CompletedSet s, String userId, String syncId, String workoutSyncId)` — maps Drift set to Supabase row format

    **CRITICAL RULES:**
    - Always write syncId to Drift BEFORE calling Supabase (safe retries)
    - Push order: cycles → workouts → sets/PRs/1RMs (FK constraints)
    - Use `Uuid().v4()` from uuid package for syncId generation
    - Supabase upsert (not insert) for idempotent retries
    - Use `_supabase.auth.currentUser!.id` as userId for Supabase rows
    - Import `dart:convert` for jsonEncode/jsonDecode (queue), `package:shared_preferences/shared_preferences.dart`, `package:uuid/uuid.dart`, `package:drift/drift.dart`

    **2. SyncState class:**
    ```dart
    class SyncState {
      final SyncStatus status;
      final DateTime? lastSyncedAt;
      final bool isAuthenticated;
      final String? errorMessage;

      const SyncState({
        this.status = SyncStatus.disabled,
        this.lastSyncedAt,
        this.isAuthenticated = false,
        this.errorMessage,
      });

      SyncState copyWith({
        SyncStatus? status,
        DateTime? lastSyncedAt,
        bool? isAuthenticated,
        String? errorMessage,
      }) => SyncState(
        status: status ?? this.status,
        lastSyncedAt: lastSyncedAt ?? this.lastSyncedAt,
        isAuthenticated: isAuthenticated ?? this.isAuthenticated,
        errorMessage: errorMessage ?? this.errorMessage,
      );
    }
    ```

    **3. SyncNotifier (Riverpod 3.x NotifierProvider pattern):**
    ```dart
    class SyncNotifier extends Notifier<SyncState> {
      @override
      SyncState build() {
        final supabase = ref.watch(supabaseClientProvider);
        if (supabase == null) return const SyncState(status: SyncStatus.disabled);

        // Listen to auth state changes
        final authSub = supabase.auth.onAuthStateChange.listen((data) {
          final isAuth = data.session != null;
          if (isAuth != state.isAuthenticated) {
            state = state.copyWith(isAuthenticated: isAuth);
            if (isAuth) _onAuthenticated();
            if (!isAuth) state = state.copyWith(status: SyncStatus.offline);
          }
        });
        ref.onDispose(authSub.cancel);

        // Listen to connectivity
        ref.listen(isOnlineProvider, (_, next) {
          next.whenData((isOnline) {
            if (!isOnline) {
              state = state.copyWith(status: SyncStatus.offline);
            } else if (state.isAuthenticated) {
              _drainQueueIfNeeded();
            }
          });
        });

        // Check current auth state (restored from SharedPreferences by supabase_flutter)
        final isAuth = supabase.auth.currentSession != null;
        return SyncState(
          status: isAuth ? SyncStatus.synced : SyncStatus.offline,
          isAuthenticated: isAuth,
        );
      }
    ```

    **Required methods on SyncNotifier:**

    - `Future<void> syncAfterWorkout(int workoutId)`:
      - If not authenticated or supabase is null → enqueue and set status to pending
      - Check connectivity: if offline → enqueue and set status to pending
      - If online + authenticated → set syncing, push workout, set synced (or error on failure)

    - `Future<void> _onAuthenticated()`:
      - Upload all local data (first-time sync), then pull latest, then drain queue
      - Set status transitions: syncing → synced (or error)

    - `Future<void> _drainQueueIfNeeded()`:
      - Check if queue has items, if so drain them
      - Set status transitions: syncing → synced (or pending if partial failure)

    - `Future<void> pullFromCloud()`:
      - Public method for manual pull
      - Set syncing → call syncService.pullLatest() → set synced or error

    **Provider declaration:**
    ```dart
    final syncProvider = NotifierProvider<SyncNotifier, SyncState>(SyncNotifier.new);
    ```

    **CRITICAL:**
    - Do NOT expose `.state` setter externally — Riverpod 3.x marks it `@protected`. All mutations happen via Notifier methods.
    - Use `ref.onDispose` to cancel auth stream subscription.
    - SyncNotifier creates SyncService internally using `ref.read(databaseProvider)` and `ref.read(supabaseClientProvider)`.
    - Wrap all async state assignments in try/catch — if notifier is disposed mid-operation, `state =` throws StateError. Catch and ignore.
    - Import supabase_provider.dart, connectivity_provider.dart, database_provider.dart, and sync_service.dart.
