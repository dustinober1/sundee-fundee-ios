       Add imports at top:
       ```dart

       import 'package:firebase_core/firebase_core.dart';
       import 'package:firebase_crashlytics/firebase_crashlytics.dart';
       ```

       Modify main() to add Crashlytics wiring (full updated main function):
       ```dart
       void main() async {
         WidgetsFlutterBinding.ensureInitialized();
         usePathUrlStrategy();

         // Initialize Firebase if configured
         try {
           await Firebase.initializeApp();
           // Wire Crashlytics error handlers
           FlutterError.onError = FirebaseCrashlytics.instance.recordFlutterFatalError;
           PlatformDispatcher.instance.onError = (error, stack) {
             FirebaseCrashlytics.instance.recordError(error, stack, fatal: true);
             return true;
           };
         } catch (_) {
           // Firebase not configured — skip Crashlytics (dev/test environment)
         }

         // Existing Supabase initialization
         const supabaseUrl = String.fromEnvironment('SUPABASE_URL');
         const supabaseAnonKey = String.fromEnvironment('SUPABASE_ANON_KEY');
         if (supabaseUrl.isNotEmpty && supabaseAnonKey.isNotEmpty) {
           await Supabase.initialize(url: supabaseUrl, anonKey: supabaseAnonKey);
         }

         final prefs = await SharedPreferences.getInstance();
         final onboardingComplete = prefs.getBool('onboarding_complete') ?? false;
         runApp(
           ProviderScope(
             overrides: [
               onboardingCompleteProvider.overrideWith(
                 () => OnboardingStatusNotifier(initialState: onboardingComplete),
               ),
             ],
             child: const SundeeFundeeApp(),
           ),
         );
       }
       ```

       Also add import for PlatformDispatcher:
       ```dart
       import 'dart:ui' show PlatformDispatcher;
       ```

    IMPORTANT:
    - Firebase.initializeApp() requires firebase_options.dart generated by `flutterfire configure`
    - The try/catch allows app to run without Firebase (local dev, CI tests)
    - FlutterError.onError catches Flutter framework errors
    - PlatformDispatcher.onError catches async/isolate errors

    NOTE: User must run `flutterfire configure` separately to generate:
    - lib/firebase_options.dart
    - android/app/google-services.json
    - ios/Runner/GoogleService-Info.plist

    Without these, Firebase.initializeApp() will throw and Crashlytics won't run (graceful degradation).
  </action>

    # Production Rollout Safety Plan

    This document defines the staged rollout process for Sundee Fundee v2.0 (Flutter) production deployment.

    ## Overview

    Production rollout uses staged percentages with telemetry gates. Each stage requires meeting crash-free rate thresholds before proceeding.

    ## Telemetry Source

    **Firebase Crashlytics** provides crash-free rate metrics:
    - Dashboard: Firebase Console → Crashlytics
    - Key metric: Crash-free users (percentage)
    - Alert threshold: <99% triggers review

    ## Staged Rollout Schedule

    | Stage | Percentage | Duration | Crash-Free Threshold | Action on Pass | Action on Fail |
    |-------|------------|----------|----------------------|----------------|----------------|
    | 1 | 1% | 24 hours | ≥99.5% | Proceed to Stage 2 | Halt + investigate |
    | 2 | 10% | 48 hours | ≥99.5% | Proceed to Stage 3 | Rollback to Stage 1 |
    | 3 | 50% | 48 hours | ≥99.0% | Proceed to Stage 4 | Rollback to Stage 2 |
    | 4 | 100% | Ongoing | ≥99.0% | Complete | Rollback to Stage 3 |

    **Total rollout duration:** ~6 days (minimum)

    ## Go/No-Go Criteria

    ### Go (Proceed to Next Stage)
    - Crash-free rate meets threshold
    - No P0/P1 bugs reported
    - User feedback sentiment neutral or positive
    - No data integrity issues observed

    ### No-Go (Halt/Rollback)
    - Crash-free rate below threshold
    - P0/P1 bug affecting core workout flow
    - Data loss or sync corruption reported
    - Significant negative user feedback pattern

    ## Rollback Procedures

    ### Android (Play Console)
    1. Open Google Play Console → Release → Production
    2. Click "Halt staged rollout"
    3. (If needed) Create new release with previous version

    ### iOS (App Store Connect)
    1. Open App Store Connect → App → App Store
    2. Remove build from release
    3. Submit previous version for review (expedited if critical)

    ### Web (Firebase Hosting)
    ```bash
    # List recent deployments
    firebase hosting:channel:list

    # Rollback to previous deployment
    firebase hosting:rollback
    ```

    ## Monitoring Checklist

    During each rollout stage, monitor:

    - [ ] Crashlytics crash-free rate
    - [ ] Crashlytics new crash clusters
    - [ ] App store reviews (Play Store, App Store)
    - [ ] Support channel feedback
    - [ ] Supabase sync error rates (if applicable)

    ## Incident Response

    If critical issue detected:

    1. **Immediate:** Halt rollout (don't wait for threshold breach)
    2. **Investigate:** Check Crashlytics stack traces, reproduction steps
    3. **Decide:** Fix-forward (hotfix) vs rollback
    4. **Communicate:** Post status to appropriate channels
    5. **Resolve:** Deploy fix or complete rollback
    6. **Post-mortem:** Document lessons learned

    ## Prerequisites Before Rollout

    - [ ] Firebase project created and configured (`flutterfire configure`)
    - [ ] Crashlytics enabled in Firebase Console
    - [ ] Android signing keys created and stored in GitHub Secrets
    - [ ] iOS provisioning profiles configured
    - [ ] All parity gate tests passing
    - [ ] DATA_MIGRATION_GUIDE.md published

    ## Contact

    Rollout owner: [Assign before launch]
    Escalation path: [Define before launch]

    ---

    *Last updated: Phase 14 (Release Hardening)*
    ```
