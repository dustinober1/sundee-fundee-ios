    Keep existing `fireConfetti` function. ADD a new `firePRConfetti` function with denser config for PR celebration:

    ```typescript
    const firePRConfetti = useCallback(() => {
      const duration = 4000;
      const end = Date.now() + duration;

      // Initial burst from both sides (locked decision: full-screen)
      confetti({ particleCount: 150, spread: 100, origin: { x: 0.25, y: 0.6 }, zIndex: 9999 });
      confetti({ particleCount: 150, spread: 100, origin: { x: 0.75, y: 0.6 }, zIndex: 9999 });

      // Sustained bursts
      const interval = setInterval(() => {
        if (Date.now() > end) { clearInterval(interval); return; }
        confetti({
          startVelocity: 20, spread: 360, ticks: 80, zIndex: 9999,
          origin: { x: Math.random(), y: Math.random() * 0.4 },
          colors: ['#26ccff', '#a25afd', '#ff5e7e', '#88ff5a', '#fcff42', '#ffa62d'],
        });
      }, 200);
    }, []);
    ```

    Return `{ fireConfetti, firePRConfetti }` from the hook.

    - Do NOT use CSS transitions for the overlay — use Framer Motion AnimatePresence (consistent with app)
    - Do NOT show one modal per exercise — combine all plateaus in one modal (Open Question 3)

    - Track `hasOverridden` state (boolean, initially false)
    - On weight input `onBlur` (NOT onChange — Pitfall 5 from research): if value differs from recommendedWeight AND `!hasOverridden`, show an inline override reason selector below the input
    - Override reason selector: use the existing `Select` component from `@/components/ui/select` with options: "Injured", "Fatigued", "Just because", "Other"
    - When user picks a reason, set `hasOverridden = true`, call `onOverrideReason(reason)`, hide the selector
    - If no `recommendedWeight` prop, component behaves exactly as before (backward compatible)

    - `onOverrideReason?: (setNumber: number, reason: WeightOverrideReason) => void`

    **3. Update `src/components/program/workout-session-view.tsx`:**

    This is the main orchestration point. Add:

    a) **Recommendation display:**
    - Accept new prop: `recommendations?: Record<string, { weight: number; source: string }>` keyed by exerciseId
    - Pass each exercise's recommendation to its `ExerciseCardV2` as `recommendedWeights` (same weight for all sets of that exercise) and `recommendationSource`

    b) **PR detection on set completion:**
    - Import `usePRDetection` from `@/hooks/use-pr-detection`
    - Add state: `prCelebration: { isVisible: boolean; prType: 'weight' | 'volume' | null }`
    - In `handleSetChange`, after recording set data, call `checkWeightPR(exerciseId, actualWeight)`
    - If weight PR detected: set prCelebration visible with type 'weight'
    - Volume PR check: after each set, compute running session volume for that exercise from setDataMap, call `checkVolumePR(workoutId, exerciseId, sessionSets)` — if true and no weight PR, set type 'volume'
    - Weight PR takes priority over volume PR (show weight PR if both)
    - Render `<PRCelebration isVisible={prCelebration.isVisible} prType={prCelebration.prType} onDismiss={() => setPrCelebration({ isVisible: false, prType: null })} />`
    - On PR detected, also save PersonalRecord to DB: `savePersonalRecord({ id: generateId(), userId, exerciseId, type, value, workoutId, date: new Date() })`

    c) **Override reason tracking:**
    - When `onOverrideReason` fires from a set, store the reason in the setDataMap for that set
    - The reason gets saved with the CompletedSet on workout completion

    d) **Plateau modal rendering:**
    - Accept new prop: `plateaus?: Array<{ exerciseName: string; adjustedWeight: number }>`
    - Add state: `showPlateauModal: boolean` (true if plateaus array is non-empty, on mount)
    - Render `<PlateauModal isOpen={showPlateauModal} plateaus={plateaus} onAcknowledge={() => setShowPlateauModal(false)} />`

    **4. Update `src/app/workout/[id]/page.tsx`:**

    Wire the recommendation and plateau logic at the page level:

    a) **Load recommendations per exercise:**
    - Import `getNextRecommendedWeight`, `wasSessionSuccessful`, `SessionResult` from `@/lib/calculations`
    - Import `getLastCompletedSetsForExercise`, `getCompletedWorkoutsForCycle` from `@/lib/db`
    - Import `detectPlateauForExercise`, `getDeloadWeight` from `@/lib/recommendations/plateau-detection`
    - Use `useEffect` to load data when a session is selected:
      - For each exercise in the selected session:
        - Get last completed sets for this exercise
        - Determine if last session was success/failure/first
        - Call `getNextRecommendedWeight(lastWeight, result, oneRepMax)`
        - Build a `recommendations` map: `{ [exerciseId]: { weight, source: "Based on..." } }`
    - For plateau detection:
      - For each exercise, call `detectPlateauForExercise(exerciseId, activeCycleId)`
      - If any return hasPlateau=true, compute deload weight via `getDeloadWeight(currentRecommendedWeight)`
      - Build `plateaus` array: `[{ exerciseName, adjustedWeight }]`
      - If plateaued, override the recommendation with the deload weight (locked decision: auto-adjust)
    - Pass `recommendations` and `plateaus` as props to `WorkoutSessionView`

    b) **Get activeCycleId:**
    - Import `getActiveCycles` from `@/lib/db`
    - In useEffect, get active cycles for user, use the first one's ID
    - If no active cycle, recommendations will use 'first' result (70% 1RM)

    c) **Handle per-exercise 1RM:**
    - Currently only uses `backSquat1RM`. Extend to look up 1RM per exercise:
    - For each exercise in session, find its 1RM from `oneRepMaxes` array
    - If no 1RM for an exercise, fall back to `prescribedWeight` (no recommendation possible)

    **Anti-patterns to avoid:**
    - Do NOT show override dialog on every keystroke — use onBlur (Pitfall 5)
    - Do NOT fire PR celebration before set data is saved to state — save first, celebrate second
    - Do NOT use the old `detectPlateauForCycle` — use `detectPlateauForExercise` per exercise
    - Do NOT show recommendations for exercises with no 1RM data — fall back gracefully
