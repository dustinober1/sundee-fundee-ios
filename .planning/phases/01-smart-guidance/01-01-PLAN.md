  <action>
    **1. Extend `src/types/workout.ts`:**
    - Add `WeightOverrideReason` type: `'injured' | 'fatigued' | 'just_because' | 'other'`
    - Add optional `overrideReason?: WeightOverrideReason` to `CompletedSet` interface
    - Add `PRType` type: `'weight' | 'volume'`
    - Add `PersonalRecord` interface: `{ id: string; userId: string; exerciseId: string; type: PRType; value: number; workoutId: string; date: Date; }`

    **2. Update `src/lib/db/dexie.ts`:**
    - Import `PersonalRecord` from `@/types/workout`
    - Add `personalRecords!: Table<PersonalRecord, string>` to the class
    - Add `this.version(4).stores({...})` — copy ALL tables from version 3 and add `personalRecords: 'id, userId, exerciseId, type, date'`
    - `overrideReason` on CompletedSet needs no index (it's just a field)

    **3. Add DB functions to `src/lib/db/index.ts`:**
    - `savePersonalRecord(pr: PersonalRecord): Promise<void>` — `db.personalRecords.add(pr)`
    - `getPersonalRecordsForExercise(userId: string, exerciseId: string): Promise<PersonalRecord[]>` — query by userId then filter exerciseId
    - `getLastCompletedSetsForExercise(exerciseId: string, activeCycleId: string, limit: number): Promise<CompletedSet[]>` — join through completedWorkouts by activeCycleId, get workoutIds, then query completedSets by workoutId and filter exerciseId, ordered by createdAt descending, limited
    - `getCompletedWorkoutsForCycle(activeCycleId: string, limit?: number): Promise<CompletedWorkout[]>` — query completedWorkouts where activeCycleId equals, reverse sort, optional limit
    - Import `PersonalRecord` type from `@/types`

    **Anti-patterns to avoid:**
    - Do NOT forget to list ALL existing tables in version(4) stores — Dexie requires all tables in every version declaration
    - Do NOT add indexes for `overrideReason` — it's a rarely-queried field
  </action>

  <action>
    **1. Update `WorkoutSessionView` to collect per-set data:**

    Currently `handleSetChange` only tracks a key in a `Set<string>` for completion tracking. Extend it to ALSO collect actual set data in a `Map` or `Record`:

    - Add state: `const [setDataMap, setSetDataMap] = useState<Record<string, { exerciseId: string; setNumber: number; prescribedWeight: number; prescribedReps: number; actualWeight: number; actualReps: number }>>({})`
    - When `handleSetChange` fires, store the set data keyed by `${exerciseIndex}-${setNumber}`
    - Pass the exercise's `exercise` field (the exerciseId string like `'back-squat'`) from the exercises array through `ExerciseCardV2` so each set knows its exerciseId
    - Update the `onComplete` callback type from `(data: { completed: boolean }) => void` to `(data: { completed: boolean; sets: CollectedSetData[] }) => void` where `CollectedSetData` is `{ exerciseId: string; setNumber: number; prescribedWeight: number; prescribedReps: number; actualWeight: number; actualReps: number }`
    - When "Complete Workout" is clicked, gather all entries from `setDataMap` and pass as `sets` array

    **2. Update `ExerciseCardV2` to pass exerciseId and prescribedWeight/Reps to set change:**

    Currently `onSetChange` signature is `(setNumber: number, data: { weight: number; reps: number }) => void`. Extend it to include prescribedWeight and prescribedReps:
    - Change `onSetChange` to pass: `(setNumber: number, data: { weight: number; reps: number; prescribedWeight: number; prescribedReps: number })`
    - Also add `exerciseId` prop to `ExerciseCardV2Props` so the parent can identify which exercise each callback is for
    - In `WorkoutSessionView`, pass `exercise.exercise` as `exerciseId` to each `ExerciseCardV2`

    **3. Wire `onComplete` in `workout/[id]/page.tsx`:**

    Replace the no-op `onComplete={() => {}}` with a real handler:
    ```
    - Import `saveCompletedWorkout`, `saveCompletedSet` from `@/lib/db`
    - Import `generateId` from `@/lib/utils`
    - Import `useUser` from `@/contexts/user-context`
    - Get user and active cycle info from context
    - On complete: generate a workoutId, call saveCompletedWorkout with { id, userId, activeCycleId, programId, week, sessionId, completedAt }, then loop through sets calling saveCompletedSet for each with { id: generateId(), workoutId, exerciseId, setNumber, prescribedWeight, actualWeight, prescribedReps, actualReps, createdAt: new Date() }
    - After saving, navigate back or show a completion state
    ```
    Note: For `activeCycleId`, query it from the user context or DB. If no active cycle exists yet, generate one or use a fallback ID. The important thing is data gets saved.

    **4. Create `src/components/ui/tooltip.tsx` (shadcn-style Radix wrapper):**

    Build using `radix-ui` package's Tooltip export (already installed as `radix-ui` v1.1.6):
    ```typescript
    'use client';
    import { Tooltip as TooltipPrimitive } from 'radix-ui';
    import { cn } from '@/lib/utils';
    ```
    Export: `Tooltip`, `TooltipTrigger`, `TooltipContent`, `TooltipProvider`
    - `TooltipContent` should be a `forwardRef` wrapping `TooltipPrimitive.Content` with styling: `z-50 overflow-hidden rounded-md bg-primary px-3 py-1.5 text-xs text-primary-foreground animate-in fade-in-0 zoom-in-95`
    - `sideOffset` default to `4`

    **5. Add `TooltipProvider` to `src/contexts/providers.tsx`:**

    Import `TooltipProvider` from `@/components/ui/tooltip` and wrap the existing children:
    ```
    <ExerciseProvider>
      <UserProvider>
        <CycleProvider>
          <TooltipProvider delayDuration={300}>
            {children}
          </TooltipProvider>
        </CycleProvider>
      </UserProvider>
    </ExerciseProvider>
    ```

    **Anti-patterns to avoid:**
    - Do NOT leave `onComplete` as a no-op — this is the entire point of this task
    - Do NOT import `@radix-ui/react-tooltip` directly — use the `radix-ui` package (it's the installed one)
    - Do NOT forget to add `TooltipProvider` — Radix Tooltip crashes without it (Pitfall 6 from research)
