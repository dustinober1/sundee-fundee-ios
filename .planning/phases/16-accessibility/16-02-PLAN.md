Per AUD-05 and CONTEXT.md decision "Use SwiftUI's built-in relative sizing for all body text; keep display headings fixed-size":

**Strategy:** Replace fixed-size `Font.system(size:)` with `Font.system(size:, design:).scaledToFit()` wrapped in a View extension, OR use SwiftUI's built-in text styles with custom weights. The cleanest approach for preserving the Art Deco design while enabling Dynamic Type is to use `.scaledToFit()` on body/label/mono fonts.

However, `.scaledToFit()` is not available directly on Font. The correct SwiftUI approach is to wrap text in `.dynamicTypeSize(...)` modifiers at the view level, or better: switch body/label/mono to use SwiftUI's built-in text styles as a base and customize weight/design:

**Implementation approach -- use `@Environment(\.dynamicTypeSize)` is NOT the right pattern. The correct pattern for global font tokens is:**

Replace the static `Font` properties with computed properties or ViewModifier approach. The simplest correct approach:

```swift
// Body - content text (SCALABLE via minimumScaleFactor + relativeSize)
public static let bodyLarge = Font.system(size: 16, weight: .regular)
public static let bodyMedium = Font.system(size: 14, weight: .regular)
public static let bodySmall = Font.system(size: 12, weight: .regular)
```

**Actual correct approach:** Use SwiftUI's `Font.custom()` with `size:` that respects Dynamic Type by applying `.font()` modifier at the Text level, then adding `.dynamicTypeSize(...)` is for restricting. The RIGHT way to make fonts scale is to use relative text styles:

For body text, replace fixed-size fonts with SwiftUI text styles that map closely to the current sizes:
- `bodyLarge` (16pt) -> `Font.title3.weight(.regular)` (scales from ~16pt at default)
- `bodyMedium` (14pt) -> `Font.body.weight(.regular)` (scales from ~14pt at default, this IS the standard body)
- `bodySmall` (12pt) -> `Font.subheadline.weight(.regular)` (scales from ~12pt at default)
- `labelLarge` (12pt) -> `Font.subheadline.weight(.medium)`
- `labelMedium` (11pt) -> `Font.footnote.weight(.medium)` (scales from ~11pt)
- `labelSmall` (10pt) -> `Font.caption2.weight(.medium)` (scales from ~10pt)
- `monoLarge` (14pt) -> `Font.body.weight(.regular).monospaced()` -- BUT monospaced design cannot be combined with built-in styles easily. Instead use `Font.system(size: 14, weight: .regular, design: .monospaced)` and add `.minimumScaleFactor(0.5)` at the Text level where used.

Actually, the simplest and most correct approach: **keep the same fixed-size Font definitions but add a ViewModifier that applies `.minimumScaleFactor(0.7)` to prevent clipping at large Dynamic Type sizes, AND for body text specifically, switch to relative text styles.**

**Final correct approach (implementation):**

1. Keep display and headline fonts FIXED (per CONTEXT.md decision). No changes.
2. For body/label fonts, switch to SwiftUI's built-in relative text styles:
   - `bodyLarge` -> `Font.title3` (default ~16pt, scales with Dynamic Type)
   - `bodyMedium` -> `Font.body` (default ~14pt at default size, standard body style)
   - `bodySmall` -> `Font.subheadline` (default ~12pt)
   - `labelLarge` -> `Font.subheadline.weight(.medium)`
   - `labelMedium` -> `Font.footnote.weight(.medium)`
   - `labelSmall` -> `Font.caption2.weight(.medium)`
3. For mono fonts, keep fixed-size but add a view-level guideline -- since mono is used for metrics/numbers in compact spaces, keep them fixed but verify they don't clip. Add `.lineLimit(1)` and `.minimumScaleFactor(0.5)` at usage sites that are constrained (stat cards, set rows, weight fields).

4. Add a ViewModifier `ArtDecoScalableText` that can be applied to any Text view to ensure it scales:
   ```swift
   extension View {
       public func artDecoScalableText() -> some View {
           self.minimumScaleFactor(0.7)
               .lineLimit(1)
       }
   }
   ```
   Apply this to StatCard values, mono numbers, and constrained text elements.

5. Since switching from `Font.system(size:)` to `Font.body` / `Font.subheadline` changes the default size slightly at standard Dynamic Type, verify the visual appearance is close enough. The SwiftUI text styles are:
   - `.title3` = ~17pt at default (close to 16pt bodyLarge)
   - `.body` = ~17pt at default (close to 14pt bodyMedium -- may need adjustment)
   - `.subheadline` = ~15pt at default (close to 12pt bodySmall -- may need adjustment)

   If the sizes diverge too much, an alternative approach is to use `UIFontMetrics` to scale custom sizes:
   ```swift
   public static var bodyMedium: Font {
       let baseSize: CGFloat = 14
       let metrics = UIFontMetrics(forTextStyle: .body)
       let scaledSize = metrics.scaledValue(for: baseSize)
       return Font.system(size: scaledSize, weight: .regular)
   }
   ```
   This preserves exact base sizes while enabling Dynamic Type scaling. **USE THIS APPROACH** -- it gives the most control and matches the current design pixel-perfectly at default size while scaling correctly.

**Implementation steps:**
1. Convert `bodyLarge`, `bodyMedium`, `bodySmall` from `static let` to `static var` computed properties that use `UIFontMetrics` to scale the base size
2. Convert `labelLarge`, `labelMedium`, `labelSmall` similarly
3. Convert `monoLarge`, `monoMedium`, `monoSmall` similarly
4. Keep `displayLarge`, `displayMedium`, `displaySmall` and `headlineLarge`, `headlineMedium`, `headlineSmall` as `static let` with fixed sizes (per CONTEXT.md decision)
5. Add `.minimumScaleFactor(0.5)` and `.lineLimit(1)` to the StatCard value text and other constrained views to prevent clipping at extreme sizes

Note: `UIFontMetrics` requires `import UIKit`. Use `#if os(iOS)` guard or just import UIKit since this is an iOS app.

Per AUD-06 and CONTEXT.md decision "Adjust Art Deco colors minimally (darken orange, lighten cream) until WCAG AA passes":

**WCAG AA requires:**
- Normal text (< 18pt or < 14pt bold): minimum 4.5:1 contrast ratio against background
- Large text (>= 18pt or >= 14pt bold): minimum 3:1 contrast ratio against background
- UI components and graphical objects: minimum 3:1 contrast ratio

**Calculate current contrast ratios against cream background (#f4f0df, luminance ~0.87):**

Using relative luminance formula: L = 0.2126*R + 0.7152*G + 0.0722*B (where R,G,B are linearized)

Contrast ratio = (L1 + 0.05) / (L2 + 0.05) where L1 > L2

1. **Navy (#0d1a40) on cream (#f4f0df):**
   - Navy luminance: ~0.017, Cream luminance: ~0.87
