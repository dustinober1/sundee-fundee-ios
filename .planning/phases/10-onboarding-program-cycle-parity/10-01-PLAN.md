**1. Update `flutter_app/lib/main.dart`:**
```dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:shared_preferences/shared_preferences.dart';
import 'app.dart';
import 'shared/providers/onboarding_status_provider.dart';

void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final prefs = await SharedPreferences.getInstance();
  final onboardingComplete = prefs.getBool('onboarding_complete') ?? false;
  runApp(
    ProviderScope(
      overrides: [
        onboardingCompleteProvider.overrideWith((ref) => onboardingComplete),
      ],
      child: const SundeeFundeeApp(),
    ),
  );
}
```

**2. Update `flutter_app/lib/router/router.dart`:**
- Import `onboarding_status_provider.dart`
- Read `ref.watch(onboardingCompleteProvider)` to determine initial location
- Set `initialLocation: onboardingComplete ? '/dashboard' : '/onboarding'`
- Add redirect guard:
  ```dart
  redirect: (context, state) {
    final isComplete = ref.read(onboardingCompleteProvider);
    final isOnboarding = state.uri.path == '/onboarding';
    if (isComplete && isOnboarding) return '/dashboard';
    if (!isComplete && !isOnboarding) return '/onboarding';
    return null;
  },
  ```
- Keep ALL existing routes unchanged (onboarding, dashboard, programs, workout/:programId, progress)

**3. Update integration test helper `flutter_app/integration_test/helpers/app_helper.dart`:**
The `pumpApp` helper creates `ProviderScope(child: SundeeFundeeApp())` without overrides. Since `onboardingCompleteProvider` defaults to `false`, the router will start at `/onboarding` — this is correct for all existing tests that start from onboarding.

The `completeOnboarding` helper saves to DB and sets SharedPreferences, but doesn't update the provider in the test context. After calling `_handleStart()`, the provider IS updated (via `ref.read(onboardingCompleteProvider.notifier).state = true`), so the redirect should allow dashboard access.

The existing `completeOnboarding` helper should still work because:
- It enters name, taps experience, then taps Start Training
- Start Training handler updates the provider + navigates to dashboard
- The redirect guard sees isComplete=true and allows dashboard

However, verify this works by running existing tests. If the helper breaks, update it to also tap a goal option before Start Training (though with defaults pre-selected, this shouldn't be necessary).
