  <files>tests/e2e/pr-celebration.spec.ts</files>
  <action>
    Create `tests/e2e/pr-celebration.spec.ts` implementing TEST-02: verifying that the PR celebration overlay triggers when a user lifts more than their previous best.

    **Critical context — PR detection guard**: `checkWeightPR` in `use-pr-detection.ts` returns `true` only when `newWeight > currentMax && currentMax > 0`. This means the user MUST have a prior 1RM record in IndexedDB before the test workout, otherwise the first lift will never trigger a PR (by design — "no PR on first session" decision).

    **Test flow:**

    1. Navigate to `/onboarding`, call `completeOnboarding(page, 'PR Test User')`
    2. **Read the user ID from IndexedDB** — needed to seed the 1RM record with the correct userId:
       ```typescript
       const userId = await page.evaluate(async () => {
         return new Promise<string>((resolve, reject) => {
           const request = indexedDB.open('StrengthApp', 4);
           request.onsuccess = (event) => {
             const db = (event.target as IDBOpenDBRequest).result;
             const tx = db.transaction('users', 'readonly');
             const store = tx.objectStore('users');
             const getAll = store.getAll();
             getAll.onsuccess = () => {
               const users = getAll.result;
               if (users.length > 0) resolve(users[0].id);
               else reject(new Error('No user found'));
             };
             getAll.onerror = () => reject(getAll.error);
           };
           request.onerror = () => reject(request.error);
         });
       });
       ```
    3. **Seed a prior 1RM record for `pause-squat`** (the first exercise in Support Session A):
       ```typescript
       await page.evaluate(({ userId }) => {
         return new Promise<void>((resolve, reject) => {
           const request = indexedDB.open('StrengthApp', 4);
           request.onsuccess = (event) => {
             const db = (event.target as IDBOpenDBRequest).result;
             const tx = db.transaction('oneRepMaxes', 'readwrite');
             const store = tx.objectStore('oneRepMaxes');
             store.put({
               id: 'seed-1rm-pause-squat',
               userId,
               exerciseId: 'pause-squat',
               weight: 100,
               date: new Date().toISOString(),
             });
             tx.oncomplete = () => resolve();
             tx.onerror = () => reject(tx.error);
           };
           request.onerror = () => reject(request.error);
         });
       }, { userId });
       ```
       Using `pause-squat` exercise with a prior 1RM of 100 lbs. The test will enter a weight > 100 to trigger the PR.
    4. **Navigate to workout page and start session**:
       - Go to `/workout/back-squat-complete-cycle`
       - Click "Support Session A"
       - Wait for exercises to render
    5. **Enter a weight higher than the seeded 1RM (100)**:
       - Find the first weight input (`input#weight-1` or first `input[type="number"]`)
       - Fill with `'135'` — this exceeds the seeded max of 100
       - The `onSetChange` handler fires, `checkWeightPR('pause-squat', 135)` evaluates: `135 > 100 && 100 > 0` → `true`
       - PRCelebration component renders with `isVisible: true`
    6. **Assert the PR celebration overlay appears**:
       - The PRCelebration component renders a `<motion.div>` with class `fixed inset-0 z-[200]` containing "New PR!" text
       - Assert: `await expect(page.getByText('New PR!')).toBeVisible({ timeout: 5000 });`
       - Also assert the PR type subtitle: `await expect(page.getByText('New Weight Record!')).toBeVisible();`
       - For confetti detection (optional, may be flaky): `canvas-confetti` creates a `<canvas>` element in the DOM. Can check with `await expect(page.locator('canvas')).toBeVisible({ timeout: 3000 });` BUT this may be unreliable due to timing. The "New PR!" text assertion is the primary signal.
    7. **Dismiss the celebration**: Click the overlay (it has `onClick={onDismiss}`) or wait 3.5 seconds for auto-dismiss.

    **Important notes:**
    - The `useUser()` context provides `oneRepMaxes` which is loaded from Dexie on mount. We seed the 1RM BEFORE navigating to the workout page so the context loads it.
    - If the user context caches `oneRepMaxes` during onboarding (before we seed), we may need to reload. After seeding the 1RM, navigate AWAY then BACK or reload the page to ensure the context re-reads from IndexedDB.
    - The seeded 1RM also provides the prescribedWeight calculation: `Math.round(100 * 0.60) = 60 lbs` for pause-squat. The recommendation engine will suggest a weight based on this.
    - If the weight input is pre-filled with a recommendation ≤ 100, manually clearing and entering 135 should still trigger the PR.

    **Resilient assertion pattern:**
    ```typescript
    // Primary: text assertion on the PR overlay
    await expect(page.getByText('New PR!')).toBeVisible({ timeout: 5000 });
    // Secondary: the subtitle confirms weight type
    await expect(page.getByText('New Weight Record!')).toBeVisible();
    ```

  <name>Task 2: Create sync verification E2E test (TEST-03)</name>
  <files>tests/e2e/sync-verification.spec.ts</files>
  <action>
    Create `tests/e2e/sync-verification.spec.ts` implementing TEST-03: verifying that workout data syncs to a (mocked) remote after completion.

    **Background**: The `playwright.config.ts` (updated in 04-01) sets `NEXT_PUBLIC_SUPABASE_URL=http://localhost:54321` and `NEXT_PUBLIC_SUPABASE_ANON_KEY=fake-anon-key-for-testing` in the webServer env block. This makes `createClient()` return a non-null Supabase client pointing at `localhost:54321`. Without a real server there, all requests will fail — we intercept them with `page.route()`.

    **Sync flow to test**: After `handleWorkoutComplete` runs:
    1. Workout is saved to IndexedDB (Dexie)
    2. `syncAfterWorkout(workoutId)` is called
    3. If `isSyncConfigured && isOnline && isAuthenticated`:
       - Calls `pushWorkout(workoutId)` which calls `getAuthUser()` then upserts to Supabase REST
    4. If NOT authenticated:
       - Enqueues workout ID to localStorage sync queue

    **Challenge**: The user won't be authenticated via Supabase since there's no real auth server. `isAuthenticated = authUser !== null`, and `authUser` is set by `supabase.auth.onAuthStateChange`. Without valid auth state, sync will queue rather than push.

    **Two valid assertion strategies — choose the simpler one first:**

    **Strategy A (Preferred — test sync queue):**
    Test that the sync infrastructure is wired up by verifying the workout ID lands in the localStorage sync queue when the user is not authenticated (which is the default state).

    ```typescript
    test('queues workout for sync after completion', async ({ page }) => {
      // 1. Complete onboarding
      await page.goto('/onboarding');
      await completeOnboarding(page, 'Sync Test User');

      // 2. Navigate to workout, select session, fill sets, complete workout
      // (same flow as workout-flow.spec.ts)

      // 3. After "Complete Workout" click, wait briefly for async operations
      await page.waitForTimeout(1000);

      // 4. Check localStorage sync queue
      const queue = await page.evaluate(() => {
        const raw = localStorage.getItem('sync_pending_workout_ids');
        return raw ? JSON.parse(raw) : [];
      });

      // Workout ID should be in the queue (not yet synced because not authenticated)
      expect(queue.length).toBeGreaterThan(0);
    });
    ```

    **Strategy B (Advanced — mock full auth + sync):**
    If Strategy A feels insufficient for the requirement "verifies data syncs to remote mock", use full mocking:

    1. **Before any navigation**, set up `page.route()` interceptors:
       ```typescript
       const syncRequests: string[] = [];

       // Mock ALL Supabase auth endpoints
       await page.route('**/auth/v1/**', async (route) => {
         const url = route.request().url();
         if (url.includes('/auth/v1/user')) {
           // Return a fake authenticated user
           await route.fulfill({
             status: 200,
             contentType: 'application/json',
             body: JSON.stringify({
               id: 'fake-supabase-user-id',
               email: 'test@example.com',
               aud: 'authenticated',
               role: 'authenticated',
             }),
           });
         } else if (url.includes('/auth/v1/token')) {
           await route.fulfill({
             status: 200,
             contentType: 'application/json',
             body: JSON.stringify({
               access_token: 'fake-access-token',
               token_type: 'bearer',
               expires_in: 3600,
               refresh_token: 'fake-refresh-token',
               user: { id: 'fake-supabase-user-id', email: 'test@example.com' },
             }),
           });
         } else {
           await route.fulfill({ status: 200, body: '{}' });
         }
       });

       // Mock Supabase REST API — track calls
       await page.route('**/rest/v1/**', async (route) => {
         syncRequests.push(route.request().url());
         await route.fulfill({
           status: 200,
           contentType: 'application/json',
           body: JSON.stringify([]),
         });
       });

       // Mock realtime/websocket attempts
       await page.route('**/realtime/**', async (route) => {
         await route.abort();
       });
       ```

    2. **Seed a Supabase session in localStorage** before navigating:
       ```typescript
       // After route setup, before navigating to onboarding
       await page.goto('about:blank'); // Need a page context for evaluate
       await page.evaluate(() => {
         // Supabase stores session in localStorage with key pattern: sb-{ref}-auth-token
         // With URL http://localhost:54321, the ref is "localhost"
         const session = {
           access_token: 'fake-access-token',
           refresh_token: 'fake-refresh-token',
           expires_in: 3600,
           expires_at: Math.floor(Date.now() / 1000) + 3600,
           token_type: 'bearer',
           user: {
             id: 'fake-supabase-user-id',
             email: 'test@example.com',
             aud: 'authenticated',
             role: 'authenticated',
             email_confirmed_at: new Date().toISOString(),
           },
         };
         localStorage.setItem('sb-localhost-auth-token', JSON.stringify(session));
       });
       ```

    3. Navigate to `/onboarding`, complete onboarding, navigate to workout, complete workout (same flow as workout-flow.spec.ts).

    4. **Assert sync requests were made**:
       ```typescript
       // Wait for async sync to complete

       // Verify Supabase REST calls were made for completed_workouts and completed_sets
       const workoutUpserts = syncRequests.filter(url => url.includes('completed_workouts'));
       const setUpserts = syncRequests.filter(url => url.includes('completed_sets'));

       expect(workoutUpserts.length).toBeGreaterThan(0);
       expect(setUpserts.length).toBeGreaterThan(0);
       ```
