  <action>
User must perform the following manual steps (CloudKit Console is a web UI and TestFlight sync requires two physical devices — neither can be automated by Claude):

**Step 1: Populate Development Schema**
1. Build and run the app on a physical device (or simulator with iCloud-signed Apple ID) using the Development provisioning profile
2. Create one record of each type (log a workout, generate an AI workout, etc.) to ensure SwiftData auto-creates all record types in the Development CloudKit environment
3. Open CloudKit Console (https://icloud.developer.apple.com/dashboard) -> select container iCloud.com.sundeefundee.app -> Schema tab -> Development environment
4. Verify all 20 active V12 record types are listed (22 total minus 2 migration tombstones)

**Step 2: Deploy Production Schema**
5. In CloudKit Console, click "Deploy Schema Changes to Production"
6. Review the diff — confirm all expected record types appear
7. Click "Deploy" (this is irreversible — record types cannot be deleted from Production)
8. After deployment, switch to Production environment in CloudKit Console and verify the record types are present

**Step 3: Two-Device TestFlight Sync Verification**
9. Submit a TestFlight build via Xcode (Archive -> Distribute -> TestFlight)
10. Install TestFlight build on Device A and Device B (both signed into the same iCloud account)
11. On Device A: log a workout (any program session or AI workout)
12. Wait 30-60 seconds for CloudKit sync
13. On Device B: open the app and check workout history — the workout from Device A should appear
14. If sync does not appear within 2 minutes: check CloudKit Console -> Production -> Data to verify the record was written
